# WUD (What's Up Docker) для Home Assistant

[English version](README.md)

Обновления Docker-контейнеров прямо в Home Assistant: видно, что обновилось, что
изменилось, и можно обновить в один клик. Интеграция подключается к
[WUD (What's Up Docker)](https://github.com/getwud/wud) и показывает все
контейнеры, за которыми следит WUD, в **Настройки → Обновления** — рядом с
обновлениями Home Assistant и дополнений.

## Возможности

- **Каждый контейнер — обновление в Home Assistant.** Установленная и новая версия,
  имя и иконка контейнера — в *Настройки → Обновления* и на дашбордах.
- **Обновление в один клик.** Кнопка «Установить» обновляет контейнер через WUD —
  так же, как в веб-интерфейсе WUD.
- **Прогресс в реальном времени.** Процент и текущий этап (скачивание образа,
  остановка, запуск…), пока контейнер обновляется.
- **Полный список изменений по всем пропущенным версиям.** Описание берётся из
  релизов на GitHub, и если обновление сразу через несколько версий (например,
  `1.2.0` → `1.4.0`), видны изменения каждого релиза между ними: 1.4.0, 1.3.1,
  1.3.0…
- **Краткое описание в карточке.** Начало описания последнего релиза — прямо
  в карточке обновления, со ссылкой на релиз на GitHub.
- **Отдельное устройство на каждый контейнер.** С образом и установленной версией,
  подключено к устройству WUD и попадает в ту же зону.
- **Иконки контейнеров.** Та иконка, что задана в WUD (`mdi:`, Simple Icons,
  selfh.st, Font Awesome, Iconify, ссылки на картинки); если иконки нет —
  показывается иконка WUD.
- **Мгновенные изменения.** Всё, что меняется в WUD, сразу видно в Home Assistant,
  без ожидания следующего опроса.
- **Атрибуты для автоматизаций.** Тип изменения версии (major / minor / patch),
  стек, watcher, статус контейнера, ошибки WUD.

## Установка

1. HACS → Интеграции → ⋮ → *Пользовательские репозитории* → добавьте
   `https://github.com/alexeykin1984/hacks_wud` (категория *Integration*)
   и установите **WUD (What's Up Docker)**.
   Либо скопируйте папку `custom_components/wud` в `<config>/custom_components/`.
2. Перезапустите Home Assistant.
3. Настройки → Устройства и службы → *Добавить интеграцию* → **WUD**.
4. Укажите адрес WUD (например, `http://192.168.1.10:3000`) и либо логин и пароль,
   либо API-токен. Если в WUD авторизация не включена, оставьте поля пустыми.

Адрес и учётные данные потом можно поменять через «Изменить настройки» у интеграции,
не удаляя её.

## Параметры

- **Интервал опроса** — как часто запрашивать полный список контейнеров
  (по умолчанию 5 минут). Изменения и так приходят сразу.
- **Токен GitHub** — необязательно. Без токена GitHub разрешает 60 запросов в час,
  этого может не хватить, если обновлений много.

## Полезно знать

- Кнопка «Установить» появляется, только если в WUD для контейнера есть триггер
  обновления (`docker`, `dockercompose`, `command` или `nomad`). Без него обновление
  всё равно видно, просто без кнопки.
- Чтобы было описание релиза, образ должен ссылаться на свой репозиторий на GitHub.
  Правила те же, что в MQTT-интеграции WUD: метка `org.opencontainers.image.source`,
  ссылка на релиз (`wud.link.template`) или образ из `ghcr.io`.
- Промежуточные релизы показываются только при обновлении по тегу (`1.2.0` →
  `1.4.0`), от новых к старым, до 20 штук. Пре-релизы — только при обновлении до
  пре-релиза. Для образов вида `latest`, которые обновляются по digest, установленная
  версия неизвестна, поэтому показывается только последний релиз.
- Контейнеры, которые пропали из WUD, становятся недоступными и удаляются при
  следующем перезапуске Home Assistant. Их устройства можно удалить и вручную.
- Сам себя WUD по умолчанию не обновляет, см.
  [Обновление самого WUD](#обновление-самого-wud).

## Обновление самого WUD

По умолчанию WUD отказывается обновлять контейнер, в котором работает сам: при
остановке он прервал бы обновление и остался выключенным. Поэтому «Установить» у
обновления WUD заканчивается ошибкой *«Refusing to update the container WUD runs
in…»*. Есть два варианта.

**Вариант 1 — разрешить WUD обновлять себя.** Включите у триггера опцию
`SELFUPDATE` в `docker-compose.yml` WUD. В имени переменной — тип и имя триггера;
для триггера `dockercompose.app`:

```yaml
services:
  wud:
    environment:
      - WUD_TRIGGER_DOCKERCOMPOSE_APP_SELFUPDATE=true
```

Для триггера `docker` с именем `local` это `WUD_TRIGGER_DOCKER_LOCAL_SELFUPDATE=true`.
Один раз примените вручную: `docker compose up -d wud`. После этого кнопка
«Установить» работает и для WUD.

Дальше WUD передаёт обновление временному контейнеру `wud-self-update`: тот
запускает новый WUD, ждёт, пока он поднимется, и удаляет старый, а если что-то
пошло не так — возвращает старый. Что произошло, видно в его логе:
`docker logs wud-self-update`. Пока WUD перезапускается, интеграция ненадолго
недоступна и сама переподключается.

Самообновление работает, только если WUD подключён к Docker через сокет
(`/var/run/docker.sock`); с watcher'ом, у которого задан `WUD_WATCHER_{имя}_HOST`,
оно не поддерживается.

**Вариант 2 — обновлять WUD вручную.** Исключите WUD из триггера меткой:

```yaml
services:
  wud:
    labels:
      - wud.trigger.exclude=dockercompose.app
```

Обновление всё равно видно в Home Assistant, просто без кнопки «Установить».
Применяется командой `docker compose pull wud && docker compose up -d wud`.

## Как считается процент обновления

Процент идёт по этапам, которые видны в потоке событий WUD. Между этапами он
плавно растёт к следующему, поэтому при долгом скачивании не стоит на месте.
Текущий этап — в атрибуте `update_stage`.

- **0%** `starting` — запрошена установка
- **5 → 60%** `pulling` — триггер выполняется (скачивание образа)
- **65%** `stopped` — старый контейнер остановлен
- **75%** `removed` — старый контейнер удалён
- **85%** `created` — WUD увидел новый контейнер
- **95%** `started` — новый контейнер запущен
- **98%** `finalizing` — триггер завершился
- **100%** `done` — WUD проиндексировал обновлённый контейнер

У триггера `dockercompose` ответ приходит раньше, чем WUD замечает новый контейнер,
поэтому 75 / 85 / 95% обычно пропускаются.

## Разработка

```bash
python3.14 -m venv .venv && . .venv/bin/activate
pip install -r requirements_test.txt ruff
pytest --cov=custom_components.wud   # тесты (WUD и GitHub подменяются заглушками)
ruff check . && ruff format --check .
```
