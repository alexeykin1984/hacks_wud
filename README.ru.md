# WUD (What's Up Docker) для Home Assistant

[English version](README.md)

Пользовательская интеграция (ставится через HACS), которая подключает Home Assistant
к REST API [WUD](https://github.com/getwud/wud) и создаёт по одной сущности `update`
на каждый контейнер, за которым следит WUD.

## Возможности

- **Сущность обновления на каждый контейнер.** Показывает установленную и последнюю
  версию: тег, а для образов, отслеживаемых по digest, — тег и короткий digest.
  В атрибутах: тип изменения версии (major/minor/patch), watcher, стек, статус
  контейнера, ошибки.
- **Устройство на каждый контейнер.** Каждый контейнер — отдельное устройство
  (имя контейнера, модель — образ, версия — установленный тег), подключённое через
  устройство-хаб WUD. Новые устройства попадают в ту же зону, что и хаб. Имя
  устройства — это заголовок обновления в списке *Настройки → Обновления*.
- **Кнопка «Установить».** Запускает тот триггер обновления, который WUD связал
  с контейнером (`GET /api/containers/{id}/triggers`). Предпочтение отдаётся
  `docker` / `dockercompose`, затем `command` / `nomad`. Метки
  `wud.trigger.include` / `wud.trigger.exclude` учитываются так же, как в
  веб-интерфейсе WUD и в MQTT-кнопке установки.
- **Процент обновления.** Считается по этапам, которые видны в потоке событий WUD
  (`/api/events`):

  | Этап         | %      | Признак                                        |
  |--------------|--------|------------------------------------------------|
  | starting     | 0      | запрошена установка                            |
  | pulling      | 5→60   | триггер выполняется (скачивание образа)        |
  | stopped      | 65     | старый контейнер вышел из состояния `running`  |
  | removed      | 75     | старый контейнер удалён из WUD                 |
  | created      | 85     | WUD увидел новый контейнер (новый id)          |
  | started      | 95     | новый контейнер в состоянии `running`          |
  | finalizing   | 98     | вызов триггера завершился                      |
  | done         | 100    | WUD проиндексировал обновлённый контейнер      |

  Между этапами процент плавно растёт к следующему, поэтому при долгом скачивании
  он не стоит на месте. Текущий этап виден в атрибуте `update_stage`.

  У триггера `dockercompose` ответ приходит раньше, чем WUD замечает пересоздание
  контейнера, поэтому этапы 75/85/95 обычно пропускаются: после остановки сразу
  98%, а 100% — когда WUD увидит новый контейнер.
- **Описание релиза из GitHub.** Краткое описание (до 255 символов) — в карточке
  обновления, полный текст со ссылкой на релиз — в окне обновления. При обновлении
  по тегу в окне показываются и все промежуточные релизы (например, `1.2.0` → `1.4.0`
  — 1.4.0, 1.3.x и 1.3.0, от новых к старым, до 20 штук; пре-релизы — только при
  обновлении до пре-релиза). Репозиторий
  определяется так же, как в MQTT-интеграции WUD: метка
  `org.opencontainers.image.source` → ссылка на релиз (`wud.link.template`) → имя
  образа в `ghcr.io`.
- **Иконки.** Берутся из `displayIcon` контейнера (метка `wud.display.icon`) по
  правилам веб-интерфейса WUD: иконки `mdi:` показываются как обычные иконки HA;
  `sh:`/`selfhst:`/`hl:`, `si:`, `fa*:`, любые Iconify-иконки `префикс:имя`
  и ссылки — как картинка сущности. Если у контейнера своей иконки нет (в WUD это
  `mdi:docker` по умолчанию), показывается иконка WUD.
- **Мгновенные обновления.** Изменения приходят через поток событий WUD; раз в
  5 минут (настраивается) список контейнеров дополнительно запрашивается целиком.

## Установка

1. HACS → Интеграции → ⋮ → *Пользовательские репозитории* → добавьте
   `https://github.com/alexeykin1984/hacks_wud` (категория *Integration*)
   и установите **WUD (What's Up Docker)**.
   Либо скопируйте папку `custom_components/wud` в `<config>/custom_components/`.
2. Перезапустите Home Assistant.
3. Настройки → Устройства и службы → *Добавить интеграцию* → **WUD**.
4. Укажите адрес WUD (например, `http://192.168.1.150:3000`) и либо логин/пароль
   (basic auth), либо API-токен. Если в WUD авторизация не включена, оставьте поля
   пустыми.

Адрес и учётные данные потом можно поменять через «Изменить настройки» у интеграции,
не удаляя её.

## Параметры

- **Интервал опроса** — как часто запрашивать полный список контейнеров
  (по умолчанию 5 минут).
- **Токен GitHub** — необязательно. Без токена GitHub разрешает 60 запросов в час,
  этого может не хватить, если обновлений много.

## Примечания

- Кнопка установки появляется, только если в WUD с контейнером связан триггер
  обновления (`docker`, `dockercompose`, `command`, `nomad`).
- Сущности и устройства контейнеров, которые пропали из WUD, становятся
  недоступными и удаляются при следующем перезапуске Home Assistant (или устройство
  можно удалить вручную).
- Чтобы обновлять сам контейнер WUD, у триггера должна быть включена опция
  `SELFUPDATE`.

## Разработка

```bash
python3.14 -m venv .venv && . .venv/bin/activate
pip install -r requirements_test.txt ruff
pytest --cov=custom_components.wud   # тесты (WUD и GitHub подменяются заглушками)
ruff check . && ruff format --check .
```
